# Kafka Event Streaming

The Helix Engineering Platform uses Apache Kafka for asynchronous event processing between services.

## Topics

The platform publishes events to dedicated Kafka topics based on their purpose.

The primary topics include:

- `security-events` — authentication, authorization, and account security events.
- `audit-events` — user and administrative actions.
- `system-events` — operational events generated by platform services.

Producers publish events without waiting for downstream consumers to process them.

## Consumer Groups

Consumers process Kafka topics using consumer groups.

Each partition is assigned to at most one consumer within a consumer group at a time. This allows multiple consumers to process different partitions concurrently.

The security analytics service uses a dedicated consumer group for `security-events`.

## Failed Consumers

If a consumer crashes while processing an event, Kafka retains the event according to the topic retention policy.

When the consumer restarts, it resumes processing from its committed offset.

Consumers commit offsets only after successfully processing an event. This prevents an event from being permanently skipped when a consumer fails before processing completes.

## Event Processing

Security events are consumed by the security analytics service.

The service extracts features such as failed login counts, login velocity, source IP information, and authentication results.

These features are used by downstream risk evaluation components to identify potentially suspicious activity.

## Reliability

Kafka provides durable event storage and allows producers and consumers to operate independently.

Temporary consumer failures do not prevent producers from publishing new events. Consumers can catch up after recovering as long as the required events remain within the topic retention period.
